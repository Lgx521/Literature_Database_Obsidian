Rename tag branches in place and connect a local agent to your library with the new opt-in Agent MCP panel.

- Rename a tag segment and its descendants together, updating the vocabulary and paper assignments while preserving per-tag provenance, active filters and unsaved Notes. Rename visual groups independently. Conflicting names and concurrent edits stop the write.
- Open **Agent MCP** beside **Trash** for a bilingual setup guide. On desktop, prepare the connection once, then open and trust the vault folder in a new local Codex session. Other local MCP clients can use the manual Streamable HTTP connection. No additional Codex plugin, model launcher or scheduled task is installed.
- Use ten bounded tools for inbox filing, incomplete-paper enrichment, reading public PDFs, importing selected Zotero/BibTeX export files, proposing tag renames, audits and reference exports. Originals and annotation sidecars are preserved. Agents cannot invent citations or edit personal Notes, bookmarks, reading status, priority or manually completed records. Global tag proposals require Apply in Obsidian.
- Keep access device-local: MCP is off by default, desktop-only and authenticated on loopback. Secrets and absolute paths stay outside the synced vault. Review/submission records are not exposed. A connected agent can read requested public paper text and may process it remotely according to its own settings.

Requires Obsidian 1.8.7+. The optional Codex bridge requires Node.js 20+ available to Codex; normal plugin use does not. iPhone/iPad retain library features and show the MCP guide, but do not host the server. Prepare the connection separately on each computer. Zotero migration supports exported PDFs, paired annotation files and associated BibTeX, not standalone notes, collection hierarchies or annotations stored only in Zotero's database.

Validation: 44 offline synthetic regression suites on macOS, Node-free mobile runtime checks, temporary-vault MCP transport/security tests, and two-device project-configuration/stdio-bridge fixtures. The release workflow also checks Linux (skipping the two macOS-only suites), rebuilds the locked citation dependencies and validates release assets. Community review and in-app update propagation are separate from this GitHub release.
