# Maintaining Literature Database

This is the plugin source repository, not a user's vault. Never copy personal PDFs, notes, source tables, review/submission manuscripts, clipboard contents, workspace settings, recycle receipts or maintenance backups into Git. Tests must use synthetic fixtures and temporary directories.

- Edit modules in `scripts/`. Run `npm run build` to generate root `main.js` and `styles.css`; do not edit generated assets or commit them.
- `manifest.json` is authoritative for plugin identity/version. Keep `package.json` and `versions.json` consistent. Preserve the existing plugin ID unless an explicit migration is planned.
- Run `npm test`. macOS runs every suite; other platforms explicitly skip the two Finder/ditto/plutil integration suites. Keep tests offline and independent of a real vault.
- Public paper metadata has one canonical Markdown row. Collections/projects store relationships, not duplicate metadata. Preserve user notes and annotations. No per-paper Markdown records or second JSON metadata database.
- AI TL;DR summaries must retain the paper's explicitly stated proposed method name/acronym with its original spelling and capitalization (e.g. “提出 VPP2，…”), supported by the read excerpts. Do not invent or expand acronyms or confuse baselines/cited methods with the proposed method. Apply this to ordinary enrichment, approved-batch enrichment and external-agent maintenance; do not rewrite existing summaries automatically.
- Never invent citation metadata. Agents may verify titles and maintain classifications, tags and TL;DR; deterministic code handles bibliographic evidence. Preserve existing bibliography/source fields and citation keys.
- Guard source mutations against concurrent edits, retain backups, preserve paired annotation files and never overwrite a file collision.
- Removing a paper's last collection membership must offer cancel or move to recoverable trash, never leave it unassigned through that action. For papers with multiple memberships, trash actions must offer current-collection removal or library-wide trash; smart views have no current collection. Categories and writing projects count together. Guard all removal entry points and recheck memberships before writes. Other recoverable deletion is immediate. Permanent deletion is restricted to selected archive receipts, with one explicit confirmation for the selected batch. Never use a real user's trash to test it.
- Network lookup is limited to public citation identifiers/titles on Crossref/arXiv, triggered by intake/export/manual retry. No background full-library scan, scheduled agent, telemetry or uploads of manuscripts/notes.
- DeepSeek Beta is included in 4.9.0 and its feature entry is enabled by default (preserve an explicit false preference). It is an explicit exception for selected public PDF and webpage excerpts: sends text/taxonomy only after the user configures a key and clicks Organize. Never send private reviews, submissions, Notes, full source tables or credentials to any other endpoint. AI proposals prefer existing categories/tags; substantial outliers may propose new categories, subcategories and tags with reasons, reviewed before Apply; preserve all protected fields. Editable previews require title, TL;DR, tags and research placement before Apply. Only explicit human edits may replace protected descriptive fields or change existing research memberships; stamp these edits as human, retain untouched AI tag provenance and writing projects. Keep draft edits session-only until Apply. Keep the key and sync passphrase out of logs and plaintext configuration. Optional encrypted sync stores only the versioned PBKDF2/AES-GCM envelope in plugin settings; unlock is manual on each new device; optional device retention uses encrypted Obsidian SecretStorage, never plaintext plugin settings. Restore lazily when Beta opens, invalidate the remembered key when the synced envelope changes, and allow local forgetting. Never retain the sync passphrase. No automatically started requests, persistent chat or embeddings. A manually requested batch may finish while its modal is closed; retain a visible sidebar status, explicit Stop, bounded session-only results and teardown on unload. See `docs/deepseek-beta.md`.
- Follow the AGPL project license and retain third-party notices. Citation dependencies and CSL styles are locked under `scripts/vendor/`; build instructions are there. The citation bundle also embeds local helpers and i18n.js: rebuild it from locked dependencies after changes to any bundled input, then run release tests. Keep package-manager caches out of a vault and Git.
- Development and deployment are separate. Review a built version before copying its three runtime files into an explicitly named vault. Back up the old runtime first; never deploy templates over existing data.
- Detect existing source files and resolve first-run defaults only after `workspace.onLayoutReady`; an empty index during `onload` does not mean an empty vault. Keep refresh/setup actions gated until that check completes and test cold starts with a delayed file index.
- Community submission and official release publication are separate from source commits. See `docs/community-release.md`; do not claim directory approval or mobile compatibility without validation.

- Source filenames are `library.md`, `collections.md`, `reviews.md`, and `submissions.md`. Preserve the legacy table schema and Chinese stored status values; localization changes display labels only. Add translations for every new UI message in `scripts/i18n.js`. Never translate user content implicitly.

- PDF and annotation basenames are immutable from intake onward; do not normalize, suffix, truncate, or rename them. Keep old filenames as they are. Resolve new collisions with subdirectories. Paper titles are separate metadata used in the public list and detail heading; show the actual filename only as secondary detail text.
- Version 4.4.0 appends organization state and provenance to the same canonical Markdown row (13 columns), with lossless older-schema compatibility. Use `scripts/organization.js` and actor-aware `Engine.updateLibraryEntry`; never infer old authorship. Human tags use the accent color, AI tags neutral. Manually complete rows are excluded from agent work; preserve human/unknown content, memberships and personal fields. See the empty-vault AGENTS maintenance contract for the encoded provenance format.
- Direct category/project imports back up and guard both library.md and collections.md, rolling back unchanged writes on failure while preserving imported PDF files for recovery. Citation lookup runs only after intake finishes; provisional filenames are not verified titles.

- 4.4.1 adds `自动整理` to the existing selector, not a new status UI. A successful deterministic metadata pass may promote pending records, but preserves AI/manual completion. Automatically organized records remain eligible for agent TL;DR/tag enrichment. Verified publication dates fill unknown cells or refine system-owned year-only dates; protect human/unknown dates and first-version arXiv semantics. Store optional date evidence in the existing provenance cell.

## Bookmarks (4.6.0)

Bookmarks are a user-only property of the canonical public paper. The optional 14th `书签` column stores `是` or empty; old tables read as unbookmarked and migrate losslessly on the first bookmark write. Preserve all 14 cells on enrichment, intake, migration, trash and restore. Only an explicit human actor may change `bookmarked`; agents must preserve it. The bookmark smart view is not a collection and does not count toward membership/deletion rules. Group its rows by research category in sidebar order, repeating multi-category papers under every membership and putting unfiled papers last. Counts, exports and batch actions use unique canonical paths, while selection highlighting applies to every visual copy.

- Detail micro-interactions use short, one-shot opacity/transform animations only for changed controls; skip initial rendering, navigation and unchanged refreshes. Respect reduced motion, clean up exit copies/animation frames on finish or close, and never await motion before persisting data. Bookmark writes retain unchanged detail/list DOM and never dim unrelated controls; retained button callbacks must use the current row to avoid stale edit/delete conflicts.

- Share timing/easing and disclosure animation ownership through `LdbMotion`; preserve DOM/drafts during rapid reversals and release listeners/animations on close. Title and TL;DR support text selection, with double-click and Cmd/Ctrl+A limited to the focused field; selection must not include adjacent status controls.
- Inline math in titles, search results and TL;DR uses the host's lazy `loadMathJax` / `renderMath` / `finishRenderMath` API. Render only bounded `$…$` fragments with basic math commands, keeping code spans, currency, block math and unsupported expressions as source. Do not add a math engine dependency, full Markdown renderer, PDF reads or network requests. Preserve raw metadata/search/export text; copying formulas returns their source once. Reuse unchanged field DOM, batch work across frames, pause hidden views, and release queues/listeners on close. The host owns the shared MathJax lifetime; never unload it globally.
- DeepSeek credential controls reflect unlocked, remembered and locked states. Disabled inputs show an active key, and replacement/sync-passphrase changes require the corresponding edit action. Explicit Lock persists in device SecretStorage and prevents automatic restoration until manual unlock/re-entry; never discard organization previews or plans when changing credentials. Do not log credentials or retain the passphrase.

## Subcategories (4.7.0)

Categories and writing projects support one level of user-created subcategories. A paper has at most one subcategory per parent, independent of its tags and placements in other parents. Parent lists group papers once by child order with Ungrouped last; child views are flat. Hide the sidebar Ungrouped entry when it has no live papers, and show it again when papers return. Keep named empty children available as drop targets. Tags only filter. Counts, export and batch operations stay unique by PDF path. Bookmarks retain their existing category grouping.

Definitions are ordered `子类：<encoded name>` lines before a parent's membership table in `collections.md`. The optional third column is `子类`; empty means ungrouped. Read old two-column tables losslessly and extend only the affected table on the first explicit placement write. Preserve definitions and all three cells during edits, import, move, project-note updates, rename/reorder, trash and restore. Reject unknown/duplicate subcategories or stale placement/order edits. Do not create a second membership or paper record for a child. Agents must preserve user placements; assign them only when explicitly requested, never infer placements from tags.

Within a parent, dropping a paper on another child changes its placement. Across parents, normal drops add membership; Cmd-drops move the current source membership to the destination, including child targets, within the same scope. Category/project crossings still add membership. Dropping on a parent preserves an existing child placement, while a new membership starts ungrouped. Transfer feedback distinguishes new memberships, changed placements/source removal and already-present papers, using the validated source at write time. Native membership and move menus nest children only for parents with children; same-parent child moves remain available. Membership submenus contain only named children and Ungrouped. Clicking the checked entry removes that parent membership through the normal removal/last-membership safeguards; selecting another child changes placement. This parent-membership toggle is distinct from the child-reassignment action below. Leave a parent menu item's checked property unset so Obsidian builds an Electron submenu rather than a checkbox; show its membership check in the title. Removing a child or removing a paper from its child returns it to Ungrouped and preserves parent membership, notes, PDF and annotations. Last-membership/trash safeguards still count parents only. Children inherit their writing project's DDL. Public detail sections remain TL;DR, Categories, Tags, Venue, Notes, with project notes in the Notes area. Existing optional `分组标签：` preview lines remain inert prose.

Intake reveals and selects successful PDF paths (tracker rows resolve by PDF path within their destination venue), clears hiding filters and preserves the current scope's sort preference. A middle-list group drop stays in the grouped parent. Only scroll the list; metadata refresh keeps an already visible selection visible without pulling back a user who has scrolled away. Middle-list child drop targets cover the entire section, including empty children. Pointer position determines the purple target while edge scrolling or wheel scrolling; dragging must not navigate/rebuild the sidebar. Cancel animation frames and feedback on exit, drop, Escape, blur and view close. Draft/busy guards apply to every target.

Sidebar child expansion uses a short grid-height/opacity transition and rotates the existing chevron. Retain child DOM and unrelated controls; do not rerender or navigate on fold. Collapsed children are inert and hidden from accessibility, with focus returned to the toggle if needed. Preserve collapsed workspace state, guard inline rename/group drag, and respect reduced motion.

## Tag map (4.8.0)

`tags.md` is an optional vocabulary and visual-group catalog, not a second paper database. It contains only `## Group: <name>` headings and `- #canonical/tag` lines between `<!-- literature-tags:start -->` and `<!-- literature-tags:end -->`. Opening the map does not create it. The first explicit vocabulary edit or paper checkbox action saves it through the vault API; existing edits use the normal backup and exact-text concurrency guard. Preserve surrounding prose and reject malformed files, collisions, duplicate names, and families split across groups.

Groups are visual only. Hide the shared `research/` prefix in the UI but preserve canonical tags. New groups/tags are created inline; creation never assigns them to the current paper. Unused tags remain available. Checking a parent does not check children. Assignments and per-tag provenance stay in the canonical library row via human-actor updates. Keep selected paper, unsaved Notes, and unrelated control DOM intact. Agents may reuse catalog tags but must not reorganize or rename user branches without a request. The map performs no PDF reads or network calls.

Tag filters store a `tags` array in workspace view state, with OR/union semantics (any selected exact tag, case-insensitive). Migrate legacy single `tag` state on read. Keep the searchable checkbox popover open across toggles, preserve its focus/scroll, and retain selected tags absent from the latest vocabulary so users can clear them. Filtering must never write library.md or tags.md. Notes/edit guards, clear-all, mobile filter indicators, navigation and import reveal resets must include the whole array.

The tag map balances full groups left/right around its root, retaining each group’s side during the open session. Folding, inline creation, search and paper checkboxes must work on both sides without changing canonical tags or metadata. Context-menu bookmarks are public-paper actions; mixed selections add bookmarks to all, fully marked selections remove them. Batch writes validate every captured row before a single guarded mutation; preserve other metadata and keep existing controls mounted.

Mobile fixed-size icon controls must override Obsidian text-button padding within plugin scope; keep SVG aspect ratios intact. Preserve the native tablet drawer. Both tablet column expansion and phone row expansion retain the existing list/detail DOM, Notes, selection and inert state; respect reduced motion and rapid reversals.

Mobile sidebar inline names commit on blur, Done/Enter or a tap outside the input, including taps that do not transfer focus. Wait for IME composition and its final input event. Unchanged/empty mobile names exit without writing; validation failures retain the draft. Share the behavior across categories, projects, venues and child editors, serialize saves, and remove outside listeners/deferred work on finish or view close. Keep desktop behavior unchanged.

## Tag rename and workspace agents

Tag renames are explicit human operations: edit one segment inline, rename descendants and canonical assignments together, preserve verified provenance hashes under the new names, keep unknown provenance unknown, and refuse collisions. Visual-group renames only change tags.md. Use SourceTransaction backups/exact-text guards and compensation for library.md + optional tags.md. Preserve selected paper, active tag filters and unsaved Notes; never rebase a stale Notes row.

Version 4.9.0 removes Agent MCP, its server and launcher/connection setup. External agents open the vault workspace and read its AGENTS.md directly; do not recreate an MCP listener or managed Codex config. Back up, use actor-aware source helpers, compare exact source text immediately before every write and validate afterward. These are maintenance rules, not a sandbox for arbitrary external tools. Preserve protected metadata and manually completed records. See docs/workspace-agents.md. DeepSeek is optional and requires explicit user actions; it never starts an external agent.

Tag-map branch deletion is an explicit human action with an impact-count confirmation. Remove the chosen branch and descendants from vocabulary/assignments, preserve unrelated provenance and every other source cell, and use the same paired-source transaction/Notes safeguards as renaming. Draft-only DeepSeek maps may delete only new branches, never the existing global vocabulary. Save and Cancel controls are available on desktop and mobile.

Fetch DeepSeek model options from the authenticated provider `/models` endpoint after explicit enable/unlock or Get/Refresh models. Never ship a hardcoded model list. Remember only the selected model ID in settings; do not transmit paper data to the model-list endpoint. Cache the list for the session and validate the selection before PDF extraction. Cancellation retains the serial request boundary until the host request settles.

The `deepSeekBetaEnabled` settings toggle hides every Beta entry and gates the service when false. Disable stops further work, closes the modal and clears the unlocked session key, preserving saved credentials and session previews. Let an already-started Apply transaction finish safely. Re-enable never starts requests. Update entry visibility in place, preserving Notes, selected papers, scroll and unrelated DOM. Existing Beta installations retain entry visibility until explicitly disabled.

## Performance contract

Sidebar names, deadline countdowns and paper counts occupy separate flex items. Truncate only long names, never shrink the countdown or paper count. The desktop library sidebar has a 220px / 14em minimum; preserve native collapse and leave the mobile drawer width under Obsidian's control.

Coalesce source events with explicit writes, validate incomplete sync against the last good snapshot, and drain changes arriving during asynchronous refresh. Only parse changed canonical tables; manual refresh still verifies all required files. Keep row/group DOM keyed by scope and paper path, including duplicate visual copies in bookmarks, preserving selection, focus, scroll and drafts. Hidden views defer painting and resume after the host makes them visible. Map pan/zoom updates are frame-coalesced; culling must retain focused nodes/editors. Closing releases native menu callbacks, listeners, observers, frames, DOM and model/layout references; retain only primitive view preferences.

Plain-query search uses a transient result menu, with a workspace-only Search all papers checkbox. The default scope is the current filtered list; global scope searches the canonical public library, excluding private manuscripts and Inbox. Typing never filters/rebuilds the middle list. On mobile, the search-field X clears and dismisses search/keyboard without refocusing; desktop X retains focus. Constrain the result menu to 640px and the viewport, allow vertical scrolling only, and expose full title/location through native hover tooltips. Result selection revalidates the path, preserves the query, clears hiding filters and reveals the paper in its current parent when possible, otherwise in sidebar category order (then a writing project or All papers). Keep menu result DOM bounded, support IME/keyboard navigation and viewport changes, and dispose listeners, caches and frames on dismissal. Ordinary category/child/project/smart-view navigation retains the search query. Explicit clear and intake reveal retain their existing filter-reset behavior. Rebuilding a browser view must dispose its old detail-motion root and reset control caches without registering extra document visibility listeners. Dismissed collection menus revoke native callbacks and release selected rows/documents; delayed host callbacks must not mutate a closed menu.

Advanced search is local public-library/project filtering, with no author field or bibliography dependency. Workspace `advanced` state stores all/any conditions for title, exact tags, publication date, venue, TL;DR, filename and Notes. Preserve it across normal navigation; import reveal and clear-all reset it. The search-field X clears only the plain query. Condition edits and the selection-only tag map are drafts until Apply; Cancel never changes applied criteria or source files. Do not expose vocabulary creation/rename/delete in a search tag map. Dates use year/month precision, never PDF lifecycle dates; a year-only row cannot satisfy a month-specific constraint. Close search dialogs on view teardown/unload and preserve Notes/edit guards.

Search caches are view-scoped and depend on immutable row arrays and language/custom-field definitions. Replace snapshots rather than mutating rows in place; invalidate sorted order and derived values when the snapshot changes. Retain only the current sort and advanced-condition result plan, use weak row keys, and cap estimated retained search payload at 8 MiB; uncached long fields must still be searched in full. Do not cache a history of queries. Coalesce ordinary input to one animation frame, defer IME composition until commit, pause hidden views and cancel queued work/cache references on close or rebuild. Do not add a persistent index, timer, PDF reads or worker for searching.

All metadata and DeepSeek PDF extraction shares one cancellable serial queue. Read bytes only inside an active job, release loading tasks/pages in finally blocks and cancel on unload/cancellation. Never overlap buffers to work around a slow cancellation. Title export remains independent of PDF recognition and heavy citation formatting; keep export fixtures byte-for-byte compatible. Benchmark only synthetic demo data. Report JS heap and total process memory separately; do not claim a 200 MB whole-app ceiling from renderer-only measurements. See docs/performance.md.

DeepSeek owns its PDF read buffer until extraction ends. Clean it up even when cancellation, a size check or PDF initialization fails before a loading task exists. Where supported, detach the remaining ArrayBuffer with a transfer after destroying the task; the host adapter may retain the last read promise. Never modify host adapter internals or force garbage collection in production.

DeepSeek preview batches cache against immutable snapshot arrays. Replace preview `item.edits` objects instead of mutating them; validation caching is UI-only and Apply must still revalidate live sources. Coalesce preview redraws per animation frame, pause hidden documents, and release scheduled work/listeners/DOM on close. Completed/ignored items release full tag-map draft catalogs while pending edits survive reopening. Do not read tags.md until a tag map actually opens or source application needs it.

## Batch-first Inbox planning (4.9.1)

Inbox planning now covers only categories and subcategories. Step one reads up to 20 public Inbox PDFs/web resources (48,000 characters each; PDFs up to 12 pages; serialized batch at most 2,000,000 characters), sends no tag vocabulary and generates no tags or TL;DR. Reuse exact existing parent/child names; propose broad new parents or useful children only from evidence. Reasons aid review but their absence does not invalidate a plan. Each paper has one parent and at most one child. The editable preview lets users choose or type a category and child per paper; empty child means Ungrouped. Case-equivalent names merge within this batch only. Never rename live taxonomy while editing a plan.

Confirmation is session-only. Revalidate category/subcategory definitions and file/content fingerprints; unrelated tag edits do not invalidate the plan. Step two fixes the confirmed placement in code and generates titles, TL;DR and tags with editable previews. Prefer fresh existing tag vocabulary and earlier draft tags in this batch; justified new tags need reasons and user review. Tags use the usual mind map only in this second-step preview, including additions/removals and human provenance. The explicit Confirm placements and continue action accepts the displayed plan, including marked additions; manual names need no reason. Apply remains a separate guarded transaction that creates only the chosen parent/child and tags. Keep private manuscripts, bibliography and personal fields protected. Plans and proposals retain no excerpts or PDF buffers; closed views release callbacks and DOM. No SDK, background requests or embeddings.

DeepSeek accepts PDFs up to 50 MiB (shown as 50 MB), validating both file size and the read buffer. Do not silently truncate selections: retain unique paths in a session queue and process batches of 20. Each Inbox batch requires plan confirmation; Apply, ignore or clear current previews before explicitly continuing. Later batches read current applied taxonomy. Retain interrupted paths for retry, keep at most 20 previews, and never preload later PDFs. Clear results preserves queued paths; cancel remaining batches preserves current previews; unload releases both.

AI preview editors mount only while expanded and release on completed collapse, retaining draft values and selection changes. Use the shared disclosure lifecycle hooks so measurement, rapid reversals and reduced motion stay correct. Closed draft tag maps retain only additions/deletions and primitive view preferences; reconstruct against current vocabulary, preserve existing branches, and reject collisions. A late map read must not repopulate closed state. PDF excerpts must stop assembling text at the existing per-page/total character limit, with identical whitespace and UTF-16 truncation semantics.

## Web resources (4.10.0)

Web resources share the canonical `library.md` table. Its optional 16th `资源` cell is an HTML-escaped JSON object `{type:"web",id:"web:<random>",inbox:boolean,added:<ISO timestamp>}`. The first cell is an HTTP(S) Markdown link; title, tags, TL;DR, Notes and other metadata retain their existing columns. PDF rows have an empty resource cell, unchanged paths and filenames. A web row's `path` is its stable internal ID, never a filesystem path. `collections.md` references this ID using the existing membership table. Keep the ID unchanged when editing the URL.

Use `web-resources.js`, `Engine.addWebEntry` / `planWebIntake` and actor-aware updates. Deduplicate normalized URLs conservatively; preserve meaningful query parameters and fragments. Filing an Inbox web row changes its Inbox flag and memberships in one guarded transaction. Web records appear in All papers and additionally in Inbox until filed; global-search scope excludes Inbox. Trash/restore retain metadata and memberships without reading, moving or deleting attachments. URLs never enter PDF intake or citation recognition. Intake performs no network requests; a missing title uses hostname/path and stays provisional. Explicit DeepSeek organization reads selected webpage text and shares the existing Inbox plan / editable preview / Apply workflow. Prefer the official DeepSeek Fetch endpoint for the exact saved URL, falling back to direct source reading for unavailable or malformed content. Never substitute search snippets, summaries or other URLs for the original article. Keep Authorization exclusive to DeepSeek, never third-party requests. Auth, billing and rate-limit errors do not fall back. Pin the reader in confirmed Inbox plans so content fingerprints use the same representation. Cancellation/timeouts must not start fallback while the host request is unsettled. Parse HTML in a detached inert template; never attach page markup or load its assets. Bound parsing to 2 MiB HTML and 48,000 characters of extracted text; the host requestUrl transport may buffer more before the response limit is checked. Retain only proposals and evidence hashes, not HTML or extracted text. Preserve the serial request/cancellation boundary. Verify the canonical web row, URL, memberships and approved-plan content fingerprint before writes; filing an Inbox web row only changes its flag and relationships in the guarded source transaction. Inaccessible/empty pages fail before generation. AI cannot write citation metadata. Only a user may edit the URL or resource metadata. Preserve all 16 columns during maintenance and never invent publication dates or bibliography.

## Placement review (4.10.1)

Missing category/subcategory reasons never discard valid title, TL;DR or tags. Canonicalize case, Unicode compatibility forms and surrounding whitespace against existing names, without semantic merges. Ordinary proposals require explicit acceptance for new parent/child identities; Apply all excludes unresolved items, and Apply rechecks acceptance before any file movement or source write. Selecting an existing placement or Ungrouped drops the unselected addition. Inbox placements already confirmed in step one need no second acceptance. Existing research memberships bypass model placement validation and remain unchanged by default. Keep confirmation in bounded session drafts, clear UI callbacks on close, and add no retries, persistence, dependencies or background work.
